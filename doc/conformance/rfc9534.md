# RFC 9534 conformance

Micro-session ID requirements for LAG member links, implementation and tests.

Revision frozen: RFC 9534, February 2024; evidence checked 9 September 2026.
Source: [RFC 9534](https://www.rfc-editor.org/rfc/rfc9534.html).

Summary: 18 clauses: 9 Compliant, 6 Partial, 1 Gap, 2 N-A, 0 Excluded.

## Scope

stamp-suite encodes, checks and learns numeric Micro-session IDs. It does not
associate an ID with a physical LAG member: there is no egress steering onto a
member link and no check of the ingress member. The Partial rows and the Gap
row record this. External hashing alone does not satisfy the member-link
requirements, and no live LAG test is claimed. YANG mapping is outside this
RFC's scope. The Clause column quotes the RFC, trimmed.

## Notes

### Sender reply validation

When `--micro-session-id` is set, `validate_reflected_tlvs` and
`process_response` (`src/sender.rs`) require exactly one usable Micro-session ID
TLV in each reply. A reply that fails the check is discarded without changing
measurements or session state. If no reflector ID is configured, the sender
learns it from the first accepted reply to a pending probe and checks later
replies against it. Learning lasts for one sender run.

Tests: `required_msid_rejects_unusable_reply_without_consuming_state` and
`unsolicited_msid_cannot_seed_the_reflector_latch` (`src/sender.rs`), and
`tests/required_micro_session_test.rs`.
