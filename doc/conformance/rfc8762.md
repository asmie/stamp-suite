# RFC 8762 conformance

STAMP base protocol requirements, implementation and tests.

Revision frozen: RFC 8762, March 2020; source checked 22 July 2026.
Source: [RFC 8762](https://www.rfc-editor.org/rfc/rfc8762.html).

Summary: 62 clauses: 52 Compliant, 0 Partial, 0 Gap, 9 N-A, 1 Excluded.

## Scope

The matrix uses the published RFC text. Errata 8199 and 8339 apply to RFC 8972,
and RFC 8762 erratum 8518 is rejected. The Clause column quotes the RFC, trimmed.
Operator planning, key distribution and network-layer confidentiality are
outside this implementation. TLV requirements are in the
[RFC 8972 matrix](rfc8972.md). The PTP rows carry the timescale qualification
described in [PTP timescale](#ptp-timescale).

## Notes

### Symmetric reply size

The reflector pads every reply to the length of the request. Without TLVs,
`assemble_unauth_answer_symmetric` and `assemble_auth_answer_symmetric` zero-pad
to the received length. With TLVs, `assemble_unauth_answer_with_tlvs` and
`assemble_auth_answer_with_tlvs` echo the TLV area and pad, never truncating a
larger reply. A Reflected Test Packet Control TLV (RFC 10052, Type 12) can
request a different size explicitly.

### Stateful sequence numbers

With `--stateful-reflector`, each admitted session has its own counter that
starts at zero. A session rejected at capacity or during drain gets no
temporary counter, so it cannot produce a stray sequence-zero stream. When a
session expires and the same identity returns, the new session starts at zero
and queued burst copies from the old session are not sent.

### Validation before session state

Both receiver backends call the same processing path. Base validation (HMAC,
missing or revoked keys, strict parsing) runs before a session is created or
refreshed, so invalid packets cannot change sequence, counter, replay or
Follow-Up state. The shared test also runs in pnet-only builds.

### PTP timescale

Software clocks read UTC (`CLOCK_REALTIME`) for both encodings, while the PTP
epoch is TAI. The sender corrects a known reflector offset with
`--reflector-utc-offset`; the offset is not inferred from the Z bit. Hardware
clock alignment and automatic timescale selection are not implemented, so the
Compliant status covers the encoding, not TAI-correct generation. See
[timestamps and clocks](../usage.md#timestamps-and-clocks).

### Mixed clock formats

`tests/mixed_clock_test.rs` uses an independently encoded peer to check both
NTP sender with PTP reflector and PTP sender with NTP reflector, over open IPv4
and authenticated IPv6. Shared tests cover all base and extended parser
branches, known positive and negative timescale offsets, and the 2036 NTP wrap.
Real synchronization errors stay visible in the measured delays.
