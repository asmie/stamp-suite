# RFC 8762 conformance — stamp-suite

Revision frozen: RFC 8762, "Simple Two-Way Active Measurement Protocol" (March 2020) (verified 2026-07-22 against https://www.rfc-editor.org/rfc/rfc8762.html)

**Errata note (verified against the RFC Editor errata tracker on 2026-07-22):** the task brief for this matrix names verified errata **8199** and **8339** as amending RFC 8762. Both were independently re-checked at `https://errata.rfc-editor.org/eid8199` and `https://errata.rfc-editor.org/eid8339` and confirmed against the live RFC-Editor errata search (`https://errata.rfc-editor.org/search/?rfc_number=8762`, "Total Errata: 1"): eid 8199 is filed against **RFC 8972 §4.4** (the DSCP2/ECN Class-of-Service TLV wording) and eid 8339 is filed against **RFC 8972 §4.7** (the Follow-Up Telemetry TLV length-check scope) — neither touches RFC 8762's own text. This is corroborated by the codebase itself: `tests/netns_conformance.rs` (top-of-file doc comment and the Scenario 2 comment block) attributes eid 8199 to "RFC 8972 §4.4 + erratum 8199", not RFC 8762. RFC 8762's own errata record contains exactly **one** entry, eid **8518** ("add guidance for TTL-unreadable IP headers, default to 255"), which was **Rejected** by the Area Director on 2025-08-05 ("the existing RFC text contains no error") and therefore amends nothing. Consequently this matrix evaluates RFC 8762's text as published, with no errata amendments in force; eid 8199 and eid 8339 are out of scope here and belong in the RFC 8972 conformance matrix.
