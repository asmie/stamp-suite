# RFC 8972 conformance

This matrix maps each normative clause of RFC 8972 (STAMP Optional Extensions:
SSID, TLVs and HMAC) to the stamp-suite code and tests that implement it. It is
for contributors and reviewers checking protocol coverage.

Revision frozen: RFC 8972, January 2021; source checked 22 July 2026.
Source: [RFC 8972](https://www.rfc-editor.org/rfc/rfc8972.html).

Summary: 151 clauses: 143 Compliant, 0 Partial, 0 Gap, 8 N-A, 0 Excluded.

## Scope

The Clause column quotes the RFC text, trimmed. The matrix includes the
verified errata [8199](https://www.rfc-editor.org/errata/eid8199) (DSCP/ECN copy
fields) and [8339](https://www.rfc-editor.org/errata/eid8339) (Follow-Up TLV
length validation). Rows cover protocol requirements and selected format
definitions; introductions, keyword boilerplate and registry administration add
no runtime requirements.

Session-admission rows (RFC8972-3-6 to 3-8) are Compliant only with
`--session-admission provisioned`; see
[Session identity and admission](#session-identity-and-admission). Clock-source
values are operator declarations; physical clock synchronization is not
verified. The [rollup](README.md) explains scoring and verification limits.

## Notes

### Session identity and admission

`--session-admission provisioned` with repeated `--reflector-session` entries
makes the reflector admit only provisioned identities (SSID, both UDP endpoints
and the optional micro-session ID). Runtime expiry keeps the provisioned list.
The default permissive mode discovers sessions from traffic and does not meet
RFC8972-3-7 or RFC8972-3-8. Both backends key session state by the actual packet
destination. See [Session provisioning](../usage.md#session-provisioning).

### Sender TLV validation

`validate_reflected_tlvs` evaluates all flags and the HMAC before it consumes
any reflected TLV value. A U-flagged TLV is skipped, the first M-flagged TLV
stops processing of the rest, and any I flag or HMAC failure blocks all values.
A Micro-session ID, Access Report acknowledgment or congestion signal is
therefore never taken from a TLV that fails these checks. A property test mixes
flags to exercise these boundaries.

### TLV echo on the reflector

The reflector parses every TLV into `TlvList` and writes all of them back,
recognized or not, unless the whole packet is dropped (HMAC, session admission
or rate limits). Semantic handlers update recognized TLVs in place and never
remove them.

### Per-copy telemetry refresh

`refresh_telemetry` rewrites the Direct Measurement counters and Follow-Up
Telemetry fields from the session immediately before each copy is sent,
including burst copies, and the final HMACs are computed after this refresh.
Session receive counts advance only after base validation; transmit counts
advance only after a successful send.

### Clock-source declarations

`--clock-sync-source` and `--hardware-clock-sync-source` declare the system and
PHC clock sources (default: local). They are independent of the NTP/PTP
timestamp format and the S bit, and the reflector overwrites any sender values.
They are operator declarations, not proof of a locked clock service. Physical
NIC clock discipline is not verified here. See
[Timestamps and clocks](../usage.md#timestamps-and-clocks).

### Location source MAC

Location processing receives no source MAC address on either backend, so the
reflector uses the RFC fallback: a SourceMac request is answered with a zeroed
Source EUI-64 sub-TLV (RFC8972-4.2.2-6). The EUI-48 and EUI-64 copy rules
(RFC8972-4.2.2-4 and 4.2.2-5) are N-A.

### Truncated Follow-Up Telemetry

A Follow-Up Telemetry TLV whose declared Length runs past the end of the packet
is caught by the parser instead. The parser sets M and semantic processing is
skipped, so the partial bytes are echoed from the request rather than zeroed.
This case qualifies the RFC8972-4.7-6 score.

### HMAC TLV added to replies

On keyed replies the reflector adds an HMAC TLV even when the request carried
none. This matrix scores RFC8972-4.8-1 under that interpretation.
