# RFC 8545 conformance — stamp-suite
Revision frozen: RFC 8545, March 2019 (verified 2026-07-22)
Summary: 8 clauses — 1 Compliant / 0 Partial / 0 Gap / 7 N-A / 0 Excluded

RFC 8545 reassigns the well-known UDP port 862 from TWAMP-Control (TCP)
to TWAMP-Test/OWAMP-Test (UDP), and clarifies that "Standards Track"
OWAMP/TWAMP require their respective TCP control protocols. stamp-suite
implements STAMP (RFC 8762/8972), which by design has no TCP control
channel at all — STAMP sessions are provisioned entirely out-of-band
(CLI flags / config file), not negotiated via OWAMP-Control or
TWAMP-Control. Consequently, the great majority of this memo's
normative content — which is phrased in terms of Control-Client/Server
message exchanges (Request-Session, Request-TW-Session,
Accept-Session, the Port field) — has no analogue in a STAMP
implementation and is marked N-A below, per the assignment's guidance
to mark OWAMP/TWAMP-Control-specific clauses N-A. The one clause that
is applicable — that use of the reassigned well-known port is
OPTIONAL, i.e. not mandatory-to-hardcode — is checked directly against
`configuration.rs`.

## Notes on excluded / non-extracted text
- Section 5.3 ("Impact on OWAMP-Test/TWAMP-Test Protocols") discusses using a varied 5-tuple (e.g. source port) to monitor distinct ECMP paths while optionally keeping the Receiver Port fixed at 862; it contains no RFC 2119 keywords (all-lowercase "optional", "sufficient", "recommended" do not count per this document's own §2 Requirements Language, which restricts key words to their all-capitals form) — no row created. Deployment-level guidance only; stamp-suite's independently configurable `local_addr`/`remote_port`/`local_port` (`configuration.rs`) accommodate varying any element of the 5-tuple if an operator chooses to.
- Section 6 (Security Considerations) uses only lowercase "recommended" ("the following methods are recommended: ... filtering access ... using a non-globally routable IP address ...") — not an RFC 2119 keyword instance per this document's §2, so no row created. For context only: `doc/security.md` independently documents equivalent operational guidance (open-mode exposure warnings, `CAP_NET_BIND_SERVICE` minimization, authenticated/encrypted mode for MITM protection).
- Section 7 (IANA Considerations) presents the port-reassignment table (UDP 861 → owamp-test, UDP 862 → twamp-test) as a registry fact, not an RFC 2119 keyword sentence; it is the basis for the "well-known port" evidence cited under 8545-5-1 rather than a separate row.
- Appendix A (Background on TWAMP Light) is purely historical/informative, with no RFC 2119 keywords directed at implementations; no rows created.
