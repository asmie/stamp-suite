# RFC 9503 conformance

Destination Node Address and Return Path requirements, implementation and tests.

Revision frozen: RFC 9503, October 2023.
Source: [RFC 9503](https://www.rfc-editor.org/rfc/rfc9503.html).

Summary: 27 clauses: 22 Compliant, 1 Partial, 0 Gap, 3 N-A, 1 Excluded.

## Scope

The reflector handles the Destination Node Address TLV (Type 9) and the Return
Path TLV (Type 10) with its Control Code, Return Address and Segment List
sub-TLVs. Platform limits:

- Reply source pinning and same-link replies (Control Code 0x1) use
  `IP_PKTINFO`/`IPV6_PKTINFO` and work on Linux only. Elsewhere the reflector
  uses OS source selection, and a same-link request gets U.
- SRv6 return forwarding needs `--srv6-return-forwarding`, Linux, IPv6 and the
  nix backend. In every other case the reflector replies normally and sets U.
- SR-MPLS forwarding is not supported; SR-MPLS lists always get U.
- A Return Address is honored only with `--return-path-allow-alternate`
  (default off); otherwise it gets U and the reply goes to the packet source.
- Processable first Return Paths derive child flags and validate nested framing
  and selected parameter lengths. Failed-integrity and skipped copies retain
  their values, including nested flags, so unconditional child-flag origination
  remains Partial; see [nested flags](#nested-flags).

The Clause column quotes the RFC, trimmed with `...`; the flags row summarizes
an inherited requirement by reference.

## Notes

### Nested flags

RFC 9503 Section 4.1 incorporates the RFC 8972 flag procedures for Return
Path children. The previous matrix omitted that inherited requirement. A
separate row now records the limitation rather than using successful routing
or a missing-reference count as evidence of complete flag conformance.

T22b9's Linux control sent `80 0a 00 08 80 01 00 04 00 00 00 01` and got
`00 0a 00 08 80 01 00 04 00 00 00 01`: parent U clear but used child U still
set. T22b10 repairs that successful-processing defect. The same request now
returns `00 0a 00 08 00 01 00 04 00 00 00 01`. Processed children clear U/M/I
and reserved header bits; unknown and ignored children get U. The used Control
Code's reserved value bits are also zeroed. All edits retain lengths/values
except those explicitly reserved bits, and normal reply signatures are fresh.

All child framing is checked before selecting a route. A well-framed Control
Code overrides the other parameter lengths/values, including empty lists;
it does not exempt a broken container from framing validation. Without a
Control Code, only the first Return Address and segment list own those
parameters. Unknown and duplicate children cannot change the selected route.
Malformed selected lengths or broken framing mark the first parent M/U and
the identifiable child M before any early child is modified. Later outer
extensions are unprocessed copies. A later Return Path is U and retains its
child bytes; it never replaces an unusable first owner.

Sender receipt checks the same framing/selected lengths. Received child M
stops later extension values, while child I in a recognized Return Path blocks
all extension values, including earlier ones. Location's special child-I ignore
rule does not apply. An unrecognized parent is skipped without interpreting
its child flags. Base RTT can remain usable independently of extension errors.

Failed-integrity values/digests, malformed signed outer-list copies and
already-skipped values remain untouched, including their child headers. This
can retain original nested U/M/I or reserved value bits; the unconditional
origination requirement therefore stays Partial. The exception is explicit,
not evidence that those failure flags were successfully normalized.

### Return Path actions

`src/tlv/list/processing.rs::process_return_path` turns the first Return Path
TLV into one action:

- Control Code with bit 0 clear: no reply.
- Control Code with bit 0 set: reply on the arrival interface (`SameLink`),
  or U and a normal reply when the interface is unknown.
- Return Address without `--return-path-allow-alternate`: U and a reply to the
  packet source.
- SRv6 Segment List: an SRH on the reply, ending at the Return Address when
  one is present. If the SRH cannot be sent, the reply falls back to normal
  routing with U.
- Return Address alone, when allowed: the reply goes to that address.

`Transmission::send_next` (`src/receiver/transmit.rs`) sets U before final
signing whenever interface pinning, SRH insertion or alternate-address
transmission fails and the reply falls back.

### Verification

The [independent UDP fixtures](../testing-interop.md) check Type 9 acceptance,
Type 10 U fallback, CoS, directory keys, bursts and both HMACs. They do not
cover multihomed source override or SRH forwarding.

`tests/netns_conformance.rs::scenario_3_srv6_return_path` requires successful
SRv6 transit with the Linux nix reflector. Captures before and after a router
check headers, segment progression, Hop Limit, CoS, flags, HMACs and
interleaved ordinary replies. See [namespace tests](../testing-netns.md).
